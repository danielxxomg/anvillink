# Exploration: world-aware-pricing-and-audit

## Intent

Unified SDD change: (1) per-world pricing overrides for `price.hand`/`price.all` via optional `worlds:` map and (2) append-only audit log for activations. User wants both together as one change. Global prices remain mandatory `>= 10000` and representable at `economy.fractionalDigits()`; per-world entries, when present, MUST also supply both `hand` and `all` `>= 10000` with the same scale invariant. Resolution is `player.getWorld().getName()` exact case-sensitive lookup with global fallback; unknown world -> global. Invalid per-world entry fails closed per activation (no withdrawal), mirroring global floor/precision behavior. Reload must swap the worlds map atomically. Audit is pure side-effect: new `AuditPort` + file adapter to `plugins/AnvilLink/audit.log` (configurable path), ISO timestamp + player + mode + world + price + count + result, never blocks repair transaction, swallow failures, file only, no DB.

## Approaches

### Per-world pricing

1. **Explicit Map<String, WorldPrice> in ConfigSnapshot (recommended)** — `record WorldPrice(BigDecimal hand, BigDecimal all)` pure domain; `ConfigSnapshot(Map<String,WorldPrice> worldPrices)` immutable copy. `FileConfigurationPort` extends line-scan to parse `worlds:` as described, validates each pair via `MoneyAmount` (floor) and records error messages like `worlds.<world>.hand below floor` for operator diagnostics. `RepairActivation.activate(id, uuid, worldName)` does `WorldPrice wp = cfg.worldPrices().get(worldName); BigDecimal selected = (wp != null) ? (mode==HAND ? wp.hand() : wp.all()) : (mode==HAND ? cfg.priceHand() : cfg.priceAll());` then existing `ValidatedPrice.of(selected, fractionalDigits)` enforces scale. Unknown world -> null -> global. World name match is `String.equals` case-sensitive exact per spec. Reload builds new map and swaps `AtomicReference` once; readers see atomic snapshot. TDD: parser unit tests for missing/partial/below-floor/bad-scale/duplicate/empty worlds, plus activation tests for world override, fallback, unknown, and fail-closed on invalid world entry.
   - Pros: minimal domain coupling; keeps `FileConfigurationPort` as single validation boundary; trivial selector; atomic reload already proven; case-sensitive exact is just `Map.get`.
   - Cons: hand-rolled YAML must track two additional indent levels (worlds -> world entry -> hand/all); slightly more parser branching.
   - Effort: Medium.

2. **Nested config sections with PriceCatalog abstraction (alternative)** — introduce `PriceCatalog` domain object that encapsulates `globalHand/globalAll + Map<world, PricePair>` and exposes `BigDecimal priceFor(worldName, mode)`. `FileConfigurationPort` would delegate parsing to a small `WorldPriceParser` helper. Audit/activation code calls catalog instead of direct map lookup.
   - Pros: encapsulates resolution logic in one place, reusable for future dimensions (e.g., permission group).
   - Cons: premature abstraction for two modes; catalog would need provider precision at call time anyway, so either catalog holds raw BigDecimals and activation still does `ValidatedPrice`, or catalog couples to `EconomyPort` — both add indirection with no current payoff; couples config load to runtime provider precision if validated eagerly.
   - Effort: Medium-High.

### Audit log

1. **Dedicated FileAuditAdapter with swallow + async offload (recommended)** — new pure `AuditPort` with `record AuditEntry(Instant, UUID/String, RepairMode, String world, BigDecimal price, int count, String result)`. Adapter holds `File`/`Path` resolved from `ConfigSnapshot.auditFile` (default `audit.log` in data folder, configurable absolute or relative). On `record()`, format line as `ISO_OFFSET_DATE_TIME | playerUuid | mode | world | price.toPlainString() | count | result` (tab or CSV-safe), then write via `Files.writeString(file.toPath(), line + "\n", CREATE, APPEND, SYNC?)` inside `try/catch` that swallows. To avoid blocking server thread, either (a) extend `SchedulerPort` with `runAsync(Runnable)` and call it, or (b) inject a `java.util.concurrent.Executor` (single-thread daemon) created in `AnvilLinkPlugin`. Adapter never throws; `RepairActivation` calls it in finally-like position after determining `TransactionResult`, wrapped in outer try/catch as second swallow. Rotation/privacy documented in spec: file grows unbounded until operator rotates; note GDPR - player identifiers retained; recommend `audit.maxSize` future extension but out of scope.
   - Pros: pure port, testable with temp file; hexagonal; transaction never blocked; minimal deps.
   - Cons: file I/O on main thread if sync (must address); rotation not automatic.
   - Effort: Medium.

2. **Logger-based audit (alternative, rejected)** — use `java.util.logging.Logger` or Adventure logger to emit audit lines; operators configure handler to file.
   - Pros: leverages existing `OperationalReporter`/logger, no file handling.
   - Cons: log level filtering, formatting, and rotation are outside plugin control; mixes operational log (`HIGH`/`INFO`) with audit trail; harder to guarantee append-only structured fields; violates spec's explicit `plugins/AnvilLink/audit.log` contract; testing requires capturing logger output.
   - Effort: Low but semantically wrong.

## Recommendation

- **Per-world pricing:** Approach 1 — `Map<String, WorldPrice>` in `ConfigSnapshot` with hand-rolled parser extension. Pass `worldName` String into `RepairActivation.activate(...)` from `AnvilLinkPlugin.onPlayerInteract` (server thread, `player.getWorld().getName()`). Fail structural world errors closed at parse/reload (retained prior snapshot, `reload-failure` message), unknown world falls back to global, valid world entry overrides per mode, per-activation `ValidatedPrice.of(effective, fractionalDigits)` enforces scale (including per-world scale). Parser validates floor via `MoneyAmount`. Map is `unmodifiableMap` swapped atomically.
- **Audit log:** Approach 1 — `AuditPort` + `FileAuditAdapter` with swallow and async offload. Wire in `AnvilLinkPlugin` after `FileConfigurationPort` construction so audit path comes from snapshot; on every terminal `TransactionResult` (including `NoProvider`/`InsufficientFunds`/`InvalidResponse` and `Success(ZERO)` if desired — decide in proposal) emit entry with ISO instant, `player.getName()` + UUID, `mode`, `worldName`, `price.toPlainString()` or `0`, `repairedCount`, `result` discriminator. Call is best-effort after feedback, double-swallowed, never compensates. Document rotation (operator deletes/rotates file, no automatic rotation in v1) and privacy (player data retained in cleartext, note in spec).
- **Unified change rationale for proposal:** both concerns touch `config.yml`/`ConfigurationPort`/`FileConfigurationPort`/`RepairActivation`/`AnvilLinkPlugin` and share the `worldName` resolution seam, so one SDD change is justified. Keep slices separate internally (slice 1 per-world pricing + tests, slice 2 audit port/adapter + wiring) to stay within 400-line review budget and independent testability, even though spec deltas ship together.

## Risks

- **World name vs UUID volatility:** world name is rename-sensitive; renaming a world invalidates its `worlds:` entry silently falling back to global (correct per spec's exact case-sensitive name match, but operators may expect persistence). Alternative UUID would survive rename but is opaque and not human-configurable. Spec explicitly chooses name — document the rename caveat.
- **Bukkit world resolution threading:** `player.getWorld().getName()` and `Bukkit.getWorld(worldName)`/`world.getBlockAt` in `SignPort` anonymous impl MUST be called on server thread. `onPlayerInteract` is server thread today, but if `RepairActivation` is ever invoked async, `worldName` must be captured before async hop. Passing `String worldName` into domain avoids domain importing `org.bukkit.World` and fixes the threading boundary.
- **Hand-rolled YAML fragility:** adding `worlds:` two-level nesting increases parser branching (`inWorlds`, `currentWorld`, indent detection via `startsWith(" ")`); tabs vs spaces, quoted world names with spaces/colons, and duplicate keys must be handled. No SnakeYAML fallback — regression tests must cover quoted `"world nether"` and `worlds:` empty/absent cases. Consider extracting small helper `parseWorldsSection` with exhaustive unit tests.
- **Fail-closed granularity for per-world invalid:** ambiguous whether a single bad world entry should invalidate the whole file vs just that world. Global precedent is whole-file fail-closed; per-activation fail-closed would require storing invalid entries and checking at activation time. Recommendation is whole-file fail-closed at reload (simpler, consistent) with a clear error `worlds.<name>.hand below floor`; proposal must state this explicitly to avoid operator surprise.
- **Audit file I/O blocking:** synchronous `Files.writeString(APPEND)` on server thread risks tick stall under high activation rate or slow disk. Must offload async (extend `SchedulerPort` or inject `Executor`) while still swallowing. Async introduces ordering/visibility and shutdown flush (`onDisable` should flush/close). If kept synchronous, document the bound and keep line short.
- **Privacy / GDPR / retention:** audit.log stores player UUID/name, world, price, timestamp in cleartext, retained indefinitely with no rotation. Must note in spec that operators are responsible for retention/rotation and that EU servers should consider anonymization or configurable retention; no automatic PII scrubbing in v1.
- **Rotation / disk exhaustion:** no DB, no rotation; file grows unbounded. Operator may fill disk; spec should note manual rotation (rename file, plugin recreates on next append) and potential future `audit.maxBytes`/`audit.rotate` extension. Ensure adapter uses `CREATE` not `TRUNCATE` and handles missing parent directory (`getDataFolder().mkdirs()`).
- **Domain purity regression:** temptation to pass `Player` or `World` into domain for convenience. Must keep `AuditPort`/`RepairActivation` pure (Strings/BigDecimal/UUID/Mode only); all Bukkit adaptation stays in `AnvilLinkPlugin`/`FileAuditAdapter`/`Bukkit*Port`.
- **Atomic reload with two maps:** `ConfigSnapshot` will hold both `messages` and `worldPrices` maps plus audit path; all must be defensively copied as `unmodifiableMap` before `ref.set`. Partial failure must leave `ref` untouched.
- **Price display consistency:** per-world `price` logged via `amount.toPlainString()` must match withdrawn amount (already validated); ensure audit logs effective price, not global fallback, when world override applied.
- **Testing gap:** existing `FileConfigurationPortTest`/`PricePerModeE2ETest` cover global floor/precision; new tests must cover per-world combinations (HAND override only, ALL override only, both, unknown world fallback, case-sensitive miss, below-floor per-world, bad scale per-world). Audit tests must verify non-blocking (exception swallowed), format, and configurable path.
